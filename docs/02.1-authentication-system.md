# 02.1 - Authentication System

## Overview

JWT-based authentication with bcrypt password hashing. Supports forced password change on first login (production only).

## Authentication Flow

### 1. Login Flow
```
User Input (username + password)
    ↓
POST /api/auth/login
    ↓
AuthManager.verify_password()
    ↓
Check if default password (prod only)
    ├─ Yes → Return needs_password_change: true
    └─ No → Create session + Generate JWT token
```

### 2. Password Change Flow
```
User Input (old password + new password)
    ↓
POST /api/auth/change-password
    ↓
Verify current JWT token (middleware)
    ↓
AuthManager.verify_password(old)
    ↓
AuthManager.update_user_password(new)
    ↓
Create session + Generate new JWT token
```

### 3. WebSocket Authentication
```
WebSocket connection with ?token=<jwt>
    ↓
Extract token from query params
    ↓
Verify JWT token
    ├─ Valid → Accept connection
    └─ Invalid → Reject with 403
```

## Key Components

### AuthManager Class (`core/auth.py`)

**Responsibilities**:
- Password hashing and verification (bcrypt)
- Session management (MongoDB storage)
- User credential management

**Key Methods**:
- `verify_password(password, username)` → bool
- `update_user_password(new_password, username)` → None
- `create_session(username)` → None
- `is_default_password(username)` → bool
- `_hash_password(password)` → str

### JWT Token Generation (`api/auth.py`)

```python
def create_access_token(data: dict):
    expire = datetime.now(UTC) + timedelta(hours=24)
    to_encode = data.copy()
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, JWT_SECRET_KEY, algorithm="HS256")
```

**Token Payload**:
- `username`: User identifier
- `exp`: Expiration timestamp (24 hours)

### Auth Middleware (`middleware/auth.py`)

Dependency injection for protected routes:


## Environment-Based Behavior

### Development (`NODE_ENV=development`)
- Default password login → Direct access (no password change required)
- Faster development workflow

### Production (`NODE_ENV=production`)
- Default password login → Forced password change
- Enhanced security

## API Endpoints

### POST `/api/auth/login`
**Request**:
```json
{
  "username": "admin",
  "password": "admin123"
}
```

**Response (Success)**:
```json
{
  "access_token": "eyJhbGc...",
  "username": "admin",
  "needs_password_change": false
}
```

**Response (Password Change Required)**:
```json
{
  "access_token": "",
  "username": "admin",
  "needs_password_change": true,
  "message": "Default password must be changed..."
}
```

### POST `/api/auth/change-password`
**Request** (requires Authorization header):
```json
{
  "current_password": "admin123",
  "new_password": "NewSecure123!"
}
```

**Response**:
```json
{
  "access_token": "eyJhbGc...",
  "message": "Password changed successfully"
}
```

## Security Features

1. **Password Hashing**: bcrypt with automatic salt
2. **JWT Expiration**: 24-hour token lifetime
3. **Forced Password Change**: Production safety (default password)
4. **Session Tracking**: MongoDB session storage with timestamps
5. **Token Verification**: All protected routes require valid JWT
